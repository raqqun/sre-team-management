# team/

Who the team is and what it is accountable for.

```
charter.md   What the team exists to do, and what it does not. Singleton.
ladder.md    Level expectations. Singleton.
roles/       One file per role: <role-name>.md
```

`charter.md` and `ladder.md` are single documents edited in place. Roles have a
template:

**Template:** [../templates/role.md](../templates/role.md) →
`team/roles/<role-name>.md`

A role file describes a role, not a person — what it is accountable for, and
what it is *not*, so hand-offs and gaps are visible. Its most useful section is
usually "Not this role".

## Proportion

Team size is 4 engineers. One person holds several roles; role files should say
so rather than implying a headcount the team does not have.

## Rules that apply here

**Personnel content stays factual.** Observable documented facts only — never
inferred capability, motivation, or attitude, and never inferred from on-call
metrics. Page counts and incident involvement describe the system, not the
person.

Individual performance documentation and hiring material live elsewhere, not in
this repo.
